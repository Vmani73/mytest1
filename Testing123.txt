SECTION E — Deterministic algorithm (implement EXACTLY)
================================================================================
E1) Ingestion and validation
- Read CSVs using pandas with the safe defaults.
- Apply schema_map if provided.
- Validate required columns, enums, uniqueness, and referential integrity.
- Produce a structured violations list:
  violation_id, rule_id, severity (ERROR|WARN), object_ref, message, suggested_fix

E2) Build as-is graphs and inventory
- Build FullGraph and QMGraph from as-is.
- Inventory summary counts and anomaly detection.

E3) RULE_C1_ONE_QM_PER_APP deterministic assignment with tie-breakers
For each app_id:
- candidates = connected qms in app_qm_connections (dedupe)
- if len(candidates)==1: assign
- if len(candidates)>1: score each candidate:
  score = (1000 * owned_queue_count_on_qm)
        + (100  * same_region_match)
        - (10   * disruption_penalty)

Definitions:
- owned_queue_count_on_qm = count of queues rows where qm_id=candidate
- same_region_match = 1 if app.region == qm.region else 0 (missing => 0)
- disruption_penalty = count of local queues on candidate whose name starts with "LQ_<APP_ID>_" (UNSPECIFIED heuristic; document)

Tie-break order:
1) higher score
2) higher owned_queue_count_on_qm
3) same_region_match==1
4) lexicographically smallest qm_id

If no candidates:
- create QM_<APP_ID>, add to queue_managers, connect app->qm.

Log every decision with all candidate scores.

E4) RULE_C2/RULE_C3/RULE_C5 canonical producer->consumer transformation
For each flow (P,C,E):
- QM_P = assigned QM of P; QM_C = assigned QM of C
- Ensure consumer local queue exists on QM_C:
  LQ = flow.consumer_local_queue if present else LQ_<C>_<E>
  Create local queue if missing.
- Ensure XMIT exists on QM_P:
  XMIT = XMIT_<QM_P>_TO_<QM_C>
- Ensure remote queue exists on QM_P:
  RQ = RQ_<P>_TO_<C>_<E>
  remote queue must store target_qm_id=QM_C, target_queue_name=LQ, and xmit_queue_name=XMIT
- Ensure channel pair exists only when QM_P != QM_C:
  sender: <QM_P>.TO.<QM_C>   (from=QM_P,to=QM_C,type=sender)
  receiver: <QM_C>.FROM.<QM_P> (from=QM_C,to=QM_P,type=receiver)
- NEVER create per-queue channels. Exactly one channel pair per QM ordered pair.

E5) RULE_C4 channel minimisation
- required_edges = set of (QM_P,QM_C) for flows where QM_P!=QM_C
- Target channels must be exactly:
  - one sender per required edge
  - one receiver per required edge
- Remove channels not required.
- If rename_nonstandard_objects=true (default):
  - deterministically normalise names (rename or create-canonical+remove-old; choose one, document, and implement deterministically).

E6) SCC-based cycle analysis and elimination
- Compute SCCs on QMGraph. SCC size>1 => cycle.
- Remove ONLY non-required/legacy edges (channels not in required_edges) to reduce cycles.
- Never remove a required edge.
- If SCC persists due to required edges, mark UNAVOIDABLE_DUE_TO_FLOWS.

E7) RULE_C6 unused object detection and removal
Used in target means:
- QMs assigned to an app
- local queues referenced/derived for flows
- remote queues for flows
- XMIT queues for required_edges
- channel pairs for required_edges

Remove everything else. Ensure no orphans.

E8) Idempotency and determinism
- Sort every output dataset deterministically.
- Generate target twice => byte-identical exports.
- Generate target from its own outputs => no-op (diff empty).

SECTION F — Complexity scoring (EXACT formula)
================================================================================
Compute for as-is and target:

channel_count = number of channel rows (sender+receiver counted separately)
multi_qm_app_violations = count apps connected to >1 qms (as-is); target must be 0
avg_routing_hops = average shortest directed path length between QM_P and QM_C on QMGraph per flow (QM_P==QM_C -> 0; no path -> ERROR)
cycle_scc_count = number of SCCs with size>1 on QMGraph
unused_object_count = count unused objects (target must be 0)
fanout_penalty = sum over QMs max(0, out_degree - FANOUT_THRESHOLD)
fanin_penalty = sum over QMs max(0, in_degree - FANIN_THRESHOLD)
total_mq_objects = num_qms + num_queues + num_channels

Defaults:
FANOUT_THRESHOLD=5
FANIN_THRESHOLD=5

ComplexityScore =
(5 * channel_count)
+ (4 * multi_qm_app_violations)
+ (3 * avg_routing_hops)
+ (3 * cycle_scc_count)
+ (2 * unused_object_count)
+ (2 * fanout_penalty)
+ (2 * fanin_penalty)
+ (1 * total_mq_objects)

Export breakdown JSON + Markdown table in report.
